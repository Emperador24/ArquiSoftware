# Clase 10 — Integrabilidad (Integrability)

## Definición

Capacidad de integrarse con otros sistemas (o de que los propios
componentes del sistema se integren entre sí).

## Factores que afectan la integrabilidad

- **Interfaces**: puntos de comunicación entre dos componentes.
- **Dependencias entre dos componentes**: sintácticas y semánticas
  (requieren conocer un mismo protocolo, formato, unidad de medida, esquema
  de datos, etc.).
- **Recursos compartidos**.
- **Secuencia temporal**.

## Tácticas para Integrabilidad (Bass/Kazman)

Tres grupos: **Limitar dependencias**, **Adaptar**, **Coordinar**.

### Limitar dependencias
- Encapsular, Usar intermediarios (Indirection), Abstraer servicios comunes
  (ya vistas en Modificabilidad).
- **Adhesión a estándares**: principalmente estándares de comunicación.
  Ejemplos: TCP/IP, HTTP, HL7-FHIR (intercambio de datos de salud), ISO
  20022 (intercambio de datos financieros), UN/EDIFACT (intercambio de
  documentos electrónicos entre organizaciones).

### Adaptar
- **Descubrimiento (Discover)**: crear "índices" para ubicar recursos
  desplegados en el sistema. Ejemplo: DNS.
- **Adaptar interfaces**: modificar interfaces para facilitar comunicación
  entre componentes o limitar su uso a lo mínimo necesario. Ejemplos:
  Interception Filters en servicios web, traducción de formatos (XML →
  JSON), API Gateways.
- **Configurar comportamiento**: pariente cercano de "Defer Binding" (visto
  en Modificabilidad); parametrizar un componente para comportarse distinto
  en ejecución según se necesite. Ejemplos: archivos de configuración,
  flags de compilación, make + configure.

### Coordinar
- **Orquestar**: coordinar ejecución de múltiples servicios sin que
  necesiten conocerse entre sí. Ejemplos: administradores de pipelines
  CI/CD (Github Actions), orquestación de Kubernetes o Docker compose,
  sistemas BPM.
- **Administrar recursos**: mediar entre los procesos y los recursos
  computacionales. Ejemplos: sistemas operativos, thread pools (Java,
  .NET), garbage collectors, ARINC 653 (Safety-Critical Avionics —
  particionamiento estricto de recursos como memoria/CPU para componentes
  de aviónica).

## Patrones de Integrabilidad

- **Wrapper / Adapter / Bridge / Mediator**: componente A que hace de
  intermediario a otro B; solo A debería acceder a B, los demás componentes
  usan A para acceder a B. Táctica relacionada: Adaptar interfaz.
- **Service-Oriented Architecture (SOA)**: forma más avanzada del patrón
  Service-Based. Múltiples servicios desplegados independientemente, con
  roles: Proveedores (proveen una interfaz que puede ser consumida) y
  Consumidores (indican sus "necesidades" de interfaz que son satisfechas
  por un proveedor). Ejemplo ilustrado: diagrama de componentes UML
  (WebStore/Warehouses/Accounting, uml-diagrams.org).
  - Ventajas: estandarización de interfaces, reutilización, independencia
    entre servicios.
  - Desventajas: mayor complejidad en protocolos de comunicación.
- **Hexagonal Architecture (HA)**: Componentes: Núcleo (lógica de negocio),
  Puertos (describen interfaces que provee y requiere), Adaptadores
  (implementación del protocolo subyacente a los puertos, ej. REST, SOAP).
  Puede usarse para implementar cada servicio individual (complementa a
  SOA/microservicios).
- **Descubrimiento dinámico (Dynamic discovery)**: táctica Discover con
  énfasis en tiempo de ejecución. Ejemplos: Netflix Eureka, Apache
  ZooKeeper, Kubernetes CoreDNS.
  - Ventaja: flexibilidad.
  - Desventaja: complejidad adicional en registro y de-registro de
    recursos.
